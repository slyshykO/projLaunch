# ProjLaunch — backlog

Обновлено 25 октября 2026 года. Здесь хранятся идеи и планы на далёкое будущее,
включая прежние незавершённые задачи, ограничения и проверки из замороженного
`CODEX-HANDOFF.md`. Наличие пункта не означает согласованный срок или приоритет.
Это список возможных будущих работ, а не журнал текущей реализации.

Главная точка входа для работы и планов — [AGENTS.md](../AGENTS.md).
Текущая работа, принятые при её реализации решения и результаты записываются
в соответствующий отдельный план. `CODEX-HANDOFF.md` остаётся неизменяемым архивом.

## Отложенные архитектурные этапы

### Постоянная модель связей проектов и репозиториев

- [ ] Вернуться к постоянным связям при необходимости ручных привязок/исключений,
  собственных имён и порядка репозиториев. Сейчас автообнаружения достаточно;
  хранение списка недоступного сервера само по себе не оправдывает этот этап.

Предварительная модель; точную SQL-схему ещё нужно определить:

- `Project` — launcher-каталог, solution или workspace.
- Постоянный `Endpoint` — среда/сервер и настройки подключения. Runtime Endpoint
  Local/WSL/SSH уже есть; сейчас настройки берутся из проекта и workspace state.
- `RepositoryBinding` — постоянные id, endpointId и путь worktree на endpoint.
  Разные worktree — разные bindings.
- `ProjectRepository` — связь projectId/repositoryBindingId, необязательное
  отображаемое имя и порядок; один repo может быть связан с разными проектами.
- Будущие SQL-таблицы: endpoints, repositories, project_repositories.
  Удаление проекта удаляет связи, а не репозитории на диске.
- Runtime connectionId/repoId не заменяет постоянный binding.
  Не создавать Git bindings автоматически при legacy SQLite import.
  Использовать уже реализованное обнаружение roots для каталогов, VS Code
  workspace и SLN/SLNX; постоянные связи в БД оно сейчас не создаёт.

### Отдельный production HTTPS/WSS API

- [ ] При появлении потребности реализовать отдельный защищённый сетевой API
  с настраиваемым портом: аутентификация, credentials/rotation,
  TLS trust/bootstrap и изоляция сессий.

Текущий HTTP/WS адаптер — development loopback под feature `network`.
Доставка/проверка/обновление сервера в WSL и SSH уже реализованы; SSH использует
OpenSSH для аутентификации, шифрования и проверки host key.
Этот этап не является предварительным условием развития Git GUI.

## Известные ограничения без согласованного этапа

### Дополнительные возможности Git GUI

Идеи для рассмотрения после основного сценария из активного плана;
сроки и приоритет не выбраны:

- [ ] Частичный stage/unstage по hunks и строкам.
- [ ] Amend последнего коммита.
- [ ] Cherry-pick и revert.

### Интерфейс и запуск проектов

- [ ] Сохранять после перезапуска ширину/видимость панели веток, фильтр,
  tree/list и свёрнутые группы. Сейчас `Branches.fs` держит их в локальном
  состоянии компонента; переключение вкладок их сохраняет.
- [ ] Убрать жёстко заданные пути Visual Studio; определить необходимость
  расширения remote launch за пределы VS Code.

### Платформы и поставка

- [ ] При необходимости расширить поддержку удалённого Git за пределы
  Linux x86_64 glibc: Windows/macOS/ARM64 и Alpine/musl сейчас не поддерживаются.
- [ ] Определить необходимость installer bundling и реализовать его отдельно.
  Сейчас он отключён; поставка — portable ZIP.

### Git API и наблюдение

Эти ограничения также были описаны в технических разделах handoff.
Их устранение не было согласовано как обязательная работа:

- [ ] Определить необходимость поддержки bare repositories; `repo.open`
  сейчас работает с worktree.
- [ ] Определить необходимость поддержки non-UTF-8 paths; сейчас такие пути
  отклоняются, Unicode поддерживается.
- [ ] При проблемах с глубокой историей оценить замену traversal через `--skip`.
  Само использование `--skip` не подтверждает проблему производительности.
- [ ] Уменьшить лишние проверки статуса от игнорируемых build outputs.
  Сейчас они могут вызывать status read, но не перезагрузку истории.
- [ ] Определить необходимость резервного обнаружения внешних изменений на
  сетевых/shared mounts, которые не сообщают filesystem notifications.
  Ручной Refresh и обновление по фокусу уже доступны.
- [ ] Определить необходимость автоматического обнаружения нового репозитория
  там, где discovery ещё не нашёл root. Сейчас он обнаруживается через
  Refresh/возврат фокуса, а watchers работают с известными roots.

### Тестовая инфраструктура и зависимости

- [ ] Определить дальнейшую роль `src-test/Tests.fs`: сейчас там только

## Ведение списка

на него. Шаги, статус реализации, принятые решения, результаты проверок и отметки
о выполнении вести непосредственно в этом плане. После завершения сохранить
здесь ссылку; подробности и историю реализации в backlog не переносить.
`CODEX-HANDOFF.md` не изменять.
