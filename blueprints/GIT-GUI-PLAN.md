# ProjLaunch — текущая работа над Git GUI

Обновлено 28 октября 2026 года.
Главная точка входа для всех планов — [AGENTS.md](../AGENTS.md).
Этот файл содержит направление, шаги, состояние работы и всю справку
о реализации этого плана: принятые решения, выполненные пункты и проверки.

## Направление

Новый фокус — довести существующий Git GUI от просмотрщика до полноценного
клиента для повседневной работы с рабочими репозиториями. Сохраняются launcher,
запуск проектов в IDE и работа с local, WSL и SSH через существующий Git-сервер.

Идеи на далёкое будущее собраны в [BACKLOG.md](BACKLOG.md), где сохранена
ссылка на этот план. [CODEX-HANDOFF.md](CODEX-HANDOFF.md) — неизменяемая
историческая справка о работе до перехода на отдельные планы.
Новые результаты по этому направлению записываются только в данный план.

Текущее состояние плана: первый этап выполнен — stage/unstage целых файлов.
Следующий предложенный этап — создание коммитов; его реализация ещё не начата.

## Отправная точка

Уже работают история и граф, ветки и переходы к коммитам, рабочие изменения,
Staged / Unstaged / Untracked, просмотр файлов и diff, восстановление вкладок,
глубины истории и прокрутки, автоматические Git-подписки.

До начала этого плана операций записи Git не было. Первый этап добавляет
stage/unstage. Нажатие на ветку по-прежнему выбирает её tip для просмотра.

## Предварительная последовательность

Пользователем выбрано направление развития. Следующая декомпозиция — предложение
для последовательных задач; точный состав и порядок ещё не утверждены.

1. **Подготовка изменений — выполнено 25.10.2026:** stage/unstage целых файлов,
   выбранных наборов и групп из панели рабочих изменений; обновление статуса и diff.
2. **Создание коммитов:** сообщение коммита, обзор подготовленных изменений,
   выполнение commit и понятное отображение результата или ошибки.
3. **Работа с ветками:** создание, переключение и удаление веток; понятное
   поведение при незакоммиченных изменениях и конфликтах.
4. **Синхронизация с remote:** fetch, pull, push, выбор remote/upstream,
   отображение прогресса и расхождения историй.
5. **Временное сохранение работы:** создание и просмотр stash, apply/pop/drop.
6. **Интеграция изменений и конфликты:** merge/rebase, список конфликтов,
   переход к их разрешению, продолжение и отмена начатой операции.

Идеи дополнительных возможностей после основного сценария вынесены в
[BACKLOG.md](BACKLOG.md#дополнительные-возможности-git-gui).

## Подход к реализации

- Делать законченными шагами: UI-действие, типизированный IPC/RPC, выполнение
  на нужном endpoint, обработка ошибок и обновление состояния после операции.
- Сохранить выбор, прокрутку и открытые diff там, где они остаются актуальными.
  Учитывать события watchers и поздние ответы параллельных запросов.
- Для операций, затрагивающих рабочие файлы или историю, явно показывать область
  действия и последствия; ошибки не должны приводить к скрытому сбросу изменений.
- Проверять операции на временных репозиториях и изолированных UI fixtures.
  Проверки должны включать изменения index/worktree и состояния репозитория,
  а не только успешный ответ команды.
- Постоянные repository bindings и отдельный HTTPS/WSS API не являются
  предварительными условиями этой работы.

Первый этап использует существующие группы рабочих изменений и подготавливает
интерфейс к созданию коммитов. Последующие этапы начинать по выбранной задаче пользователя.

## Реализация, решения и результаты

### Этап 1. Stage/unstage целых файлов — выполнен 25.10.2026

**Поведение.** В Staged есть Unstage, в Unstaged / Untracked — Stage.
Доступны кнопка в строке, независимые checkbox-выборки по группам,
действия selected и all с количеством файлов. All относится только к своей
группе. Нажатие на имя файла открывает diff, а checkbox задаёт набор для записи.
Операции проходят через тот же endpoint для local, WSL и SSH.

**Решения.** Добавлены типизированные IPC `git_stage` / `git_unstage` и RPC
`git.stage` / `git.unstage`, объявленные как дополнительные capabilities
протокола v1. Сервер сверяет пути с актуальной группой diff, самостоятельно
добавляет исходный путь переименования, отвергает пустую/устаревшую выборку
и расширение пути на посторонние изменения в подкаталоге. Предел — 10000 путей
на запрос, дополнительно действует существующий лимит RPC frame.
Пути передаются буквально, через NUL-разделённый stdin: один запуск Git на набор,
без shell и ограничений длины командной строки Windows.

Stage использует `git add --all` для выбранных путей, включая удалённые файлы;
у частично подготовленного файла индекс заменяется текущим содержимым worktree.
Unstage использует файловую форму `git reset`: она работает и до первого коммита,
не меняет HEAD и рабочие файлы. Submodule stage обновляет gitlink, а не содержимое
вложенного репозитория. Подготовка конфликтного файла отмечает его разрешённым;
UI явно предупреждает об этом в группе. `--hard`, force и удаления чужих index.lock нет.

Повторная запись блокируется по endpoint + корню worktree, даже если вкладку
закрыли и открыли снова. Это временное состояние не сохраняется в workspace JSON.
Watchers продолжают накапливать invalidations; обновление вкладки откладывается
до ответа записи. Поздний ответ diff, начатого до записи, не применяется.
После успеха **и ошибки** выполняется явное обновление статуса и групп файлов,
независимо от доступности watcher. Открытый diff перечитывается и следует за файлом
в новую группу, если путь остаётся; загруженные страницы истории и прокрутка
сохраняются. Текущие строки и diff остаются смонтированными при автоматическом
перечитывании. Ошибка записи остаётся видна, повтор выполняется только вручную:
при обрыве связи нельзя предполагать, что Git не успел изменить индекс.
Блокировка SQLite относится к каталогу проектов и не запрещает Git-операции;
конкуренцию с другими Git-клиентами контролирует штатный index.lock Git.

**Проверки.** Git workspace: 34 теста прошли (в том числе 5 новых real-Git/RPC
сценариев); дополнительно проверено stage разрешённого merge-конфликта.
Проверены содержимое index/worktree/HEAD, частичная подготовка, удаления, бинарные
и Unicode/literal-пути, unborn HEAD, переименование, ошибочная/устаревшая выборка,
замена файла каталогом и чужой index.lock. Все 23 frontend regression-скрипта
прошли; новый `test-index-changes.mjs` проверяет группы, endpoint routing,
watcher/read races, повторные нажатия, ошибки и закрытие/переоткрытие вкладки.
Нативные тесты: 45 прошли, 3 opt-in/helper пропущены; WSL-тест отдельно запущен
на Ubuntu и прошёл, включая stage/unstage Unicode-файла и сохранение его содержимого.
Clippy обоих Cargo workspace с `-D warnings` прошёл. Fantomas / cargo fmt выполнены.
`npm run build` и Linux sidecar `build-git-server ubuntu22 --release` собраны.
В изолированной браузерной fixture проверены checkbox-выбор нескольких файлов,
групповой Stage, блокировка кнопок, Unstage строки и перенос открытого diff.
Версии синхронизированы стандартными build hooks; изменения manifests/lockfiles
сохранены вместе с реализацией. Desktop debug-сборка `npm run tauri build -- --debug`
прошла с `CARGO_TARGET_DIR=build/obj/watch-native`; исполняемый файл находится
в `build/obj/watch-native/debug/projlaunch.exe`. Работавший экземпляр приложения
не останавливался. Проверка `git diff --check` прошла.

**Ограничения.** Только целые файлы, без hunk/line staging и создания коммитов.
Выбор каталогов не поддерживается; переход «файл → каталог» с пересекающимися
изменениями может потребовать внешнего Git-клиента. Внешние изменения между
показом списка и выполнением Git не блокируются; Stage берёт текущую версию файла.
Проверка SSH ограничена frontend routing и общим RPC: отдельный настоящий SSH-хост
в этой задаче не использовался.

Этот раздел не переносится в `CODEX-HANDOFF.md` или `BACKLOG.md`.

### Общий набор иконок GUI — выполнено 25.10.2026

**Решение.** Основной набор — Lucide (`lucide-react` 1.61.0).
Octicons остаётся резервом для специфических Git-обозначений, которым нет
ясного соответствия в Lucide; зависимость пока не добавлена. Новые иконки
подключаются через общий F#-модуль `src/src/ui/Icons.fs` явными named imports,
без полного реестра и загрузки с CDN. Правило закреплено в `AGENTS.md`
и [архитектурной справке](../docs/ARCHITECTURE.md#ui-icons).

**Результат.** На Lucide переведены редактирование и удаление проекта,
закрытие вкладки, diff и редактора проекта, удаление строки переменной окружения,
стрелки дерева веток и сворачивания панели. Единые параметры: 16 px в текущем UI,
stroke 1.75 и `currentColor`; доступные имена остаются у кнопок, SVG декоративные.
Старые ручные служебные SVG удалены; логотип Git и логотипы IDE сохранены.
Vite включает полный текст уведомлений Lucide/Feather в итоговый HTML после
минификации. Этап создания коммитов этим изменением не начинается.

**Проверки.** Все 23 frontend regression-скрипта прошли; проверка закрытия diff
обновлена с текстового крестика на SVG с сохранённым доступным именем кнопки.
В изолированном браузерном UI проверены раскрытие/сворачивание веток и панели,
просмотр и закрытие diff, редактор проекта и закрытие вкладки. Fantomas выполнен.
`npm run build` и повторная стандартная `.\build.bat build` прошли;
desktop executable: `src-tauri/target/debug/projlaunch.exe`.
Проверено наличие полной лицензии и используемых иконок в bundle, отсутствие
неиспользуемой контрольной иконки; gzip HTML вырос примерно на 3.2 КБ.
Версии синхронизированы build hooks. `git diff --check` с `cr-at-eol`
для текущих Windows-окончаний строк прошёл.

### Иконки управления историей — выполнено 25.10.2026

Текст Refresh заменён на Lucide `RefreshCw`, Load more — на `ListPlus`
через общий модуль `Icons`. Обе кнопки квадратные, с иконкой 16 px,
подсказкой при наведении и доступным именем с названием репозитория.
Во время загрузки сохраняется блокировка кнопок и добавлен `aria-busy`;
статус загрузки остаётся внизу панели. Условия появления Load more и Cancel
при восстановлении истории не менялись. Обновлён пользовательский справочник.

Fantomas и `.\build.bat build` прошли, версии синхронизированы.
Прошли четыре regression-скрипта: repository history, history restoration,
desktop tabs и working tree. В изолированном браузерном UI проверены обе
иконки, загрузка следующей страницы и обновление истории, включая исчезновение
Load more после последней страницы. `git diff --check` с `cr-at-eol` прошёл.

### Снятие лимита стартовых коммитов истории — выполнено 28.10.2026

**Решение и результат.** Удалён `MAX_HISTORY_ROOTS`: история больше не отклоняет
репозитории с более чем 1024 уникальными вершинами веток, тегов и HEAD.
Зафиксированные OID уже передаются в `git log` через stdin, поэтому отдельный
порог не нужен для обхода ограничения командной строки Windows. Ключи BTreeMap
уже уникальны и упорядочены; промежуточное копирование в BTreeSet удалено.
Снимок ссылок и постраничная загрузка сохранены, формат протокола не изменён.
Обновлена справка Git-сервера.

**Проверки.** Регрессионный real-Git/RPC тест теперь загружает все 2048 различных
вершин страницами по 200 коммитов, проверяя полноту и отсутствие дубликатов,
в том числе при нескольких ссылках на один коммит. Все 34 теста Git workspace
прошли: `cargo test --manifest-path crates/Cargo.toml --workspace --all-features --locked`.
Первый запуск в песочнице не смог создать `.git/config` во временных репозиториях;
повторный запуск с разрешением вне песочницы прошёл полностью. Выполнены
`npm run gen:version` (с отключённой телеметрией .NET из-за запрета доступа
к реестру в песочнице), `cargo fmt` и `git diff --check` с `cr-at-eol`.
Отслеживаемые manifests/lockfiles после генерации версии не изменились.
Перед коммитом проверены появившиеся изменения версии до
`0.5.1+17.g73e330b.dirty` во всех семи manifests/lockfiles; они включены
вместе с реализацией, изменений зависимостей в них нет.

**Ограничения.** Продолжают действовать общий лимит вывода Git 8 МиБ (включая
чтение списка refs), таймаут команд, отмена и ограничения числа cursors.
Очень большие репозитории всё ещё могут упираться в эти ограничения ресурсов.
